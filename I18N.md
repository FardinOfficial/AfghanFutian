# Localisation — English, Pashto, Afghan Dari

The site has one implementation of every page. Language is a routing and data
concern, not a second set of components.

## URLs and locale ids

| Language | Internal id | Public prefix | Example |
| --- | --- | --- | --- |
| English | `en` | — | `/about` |
| Pashto | `ps` | `/ps` | `/ps/about` |
| Afghan Dari | `fa-AF` | `/fa` | `/fa/about` |

The internal `fa-AF` id matches the HTML language tag and the translation folder;
the URL stays short (`/fa`). All ten original English URLs remain unchanged, and
each has exactly one Pashto and one Dari equivalent. `/services` still redirects
to `/sourcing` inside the active locale.

Locale precedence is:

1. an explicit `/ps` or `/fa` URL prefix;
2. the stored preference (`afghan-futian-locale`) on the unprefixed homepage;
3. English.

An explicitly typed English deep link therefore stays in English. Switching
language keeps the path, query string and hash, stores the preference, and does
not remount the page (form values and scroll position survive). Browser
back/forward re-derives the language from the URL.

## Dictionaries

`src/i18n/locales/<locale>/<namespace>.json` holds eleven namespaces:

| Namespace | Keys |
| --- | ---: |
| `common` | 160 |
| `navigation` | 36 |
| `home` | 51 |
| `pages` | 159 |
| `services` | 45 |
| `legal` | 75 |
| `contact` | 36 |
| `scheduling` | 21 |
| `media` | 25 |
| `company` | 14 |
| `email` | 64 |
| **Total** | **686** |

English source strings are the keys. `keySeparator` and `nsSeparator` are
disabled because copy contains dots, colons and em dashes. `fallbackLng` is
`en`, and the missing-key handler returns the key itself, so an omitted string
is visible in QA rather than silently hidden. A test asserts identical key sets,
key order, non-empty values and interpolation placeholders in every locale.
Terminology is centralized in `CONTENT-GLOSSARY.md`; the per-page evidence and
claim decisions are recorded in `CONTENT-REVIEW.md`.

The data modules in `src/data` stay the single source of truth for routes, ids,
media records and official company facts. `src/i18n/localize.js` walks their
strings at runtime and translates only human-facing values; machine keys such
as `id`, `name`, `to`, `href`, `status`, `index` and URLs are left untouched.
`alt` text always resolves through the `media` namespace. Select options keep
their English values (the server validates against them) while their visible
labels are translated.

## Language selector

The segmented control is `Eng | پښتو | دری` in this fixed order in every
language. It is a single LTR island, so the order never reverses in RTL. A
brand-accent plate slides between the three measured segments. It sits beside
the desktop actions and inside the hamburger menu on mobile; there are no flags
and no dropdown.

## RTL and typography

`useLocale` sets `<html lang>` and `<html dir>` on every route change. Layout
uses logical properties and Tailwind logical utilities; directional icons and
link underlines are mirrored with `rtl:` variants. Logos, photographs and map
links are never mirrored. Contact details, URLs and the Cal.com frame are
isolated LTR islands.

Fonts are local OFL-licensed WOFF2 files in `public/fonts/`:

- Vazirmatn Latin and Arabic (variable, matched latin/arabic cuts);
- Noto Sans Arabic as a Pashto glyph fallback.

`unicode-range` means only the needed subset downloads. Google Fonts links and
CSP allowances were removed; there are no external font requests. Licence texts
ship as `OFL-Vazirmatn.txt` and `OFL-Noto-Sans-Arabic.txt`.

## Forms, validation and email

`src/lib/errorCodes.js` defines stable codes shared by the browser, the server
function and the UI. The server sends codes rather than prose; the browser maps
them to English source keys and translates them in the active locale. The
visitor's locale is sent as `meta.locale` instead of `navigator.language`.

`api/contact.js` renders both the company notification and the acknowledgement
from the `email` namespace, with `dir="rtl"` and localized plain-text parts for
Pashto and Dari. Honeypot, rate limiting, dedupe and Resend delivery are
unchanged. The `mailto:` fallback still opens the same email client with the
same submitted values, but its subject, service label and footer now follow the
active locale.

`server/lib/schedulingEmail.js` uses the same dictionaries when a booking
carries a locale (`booking.locale` or Cal.com metadata `locale`) and defaults to
English otherwise. Subjects, HTML and plain text all follow the locale.

## Cal.com limitation

The official Cal.com booker embed is deliberately unchanged: same URL, iframe
attributes, origin checks and `cal.tz=Asia%2FKabul` (UTC+04:30). Cal.com's
`interfaceLocale` supports Arabic (`ar`) but does **not** list Pashto or Afghan
Dari. Substituting Arabic would mislabel the language, so the embed remains in
its supported default and the surrounding page copy is localized instead.
Pashto/Dari bookers can complete a real booking; only the embedded booker's own
interface and its provider-owned notifications are not translated. Branded
scheduling email templates are ready for a locale when Cal.com supplies one;
bookings made through the current embed default to English.

## Native-speaker review

The dictionaries, metadata, form messages and email copy have been rewritten as
Afghan Pashto and Afghan Dari rather than literal English calques. They still
need a native reviewer before launch, especially for the items below. The
current decisions and rejected alternatives are in `CONTENT-GLOSSARY.md`.

- Pashto: confirm `د توکو لېږد` / `د بار لېږد` versus `لوژستیک`; check ZWNJ and
  word spacing in long headings and animated hero lines.
- Dari: confirm ZWNJ in `تأمین\u200Cکننده`, `بسته\u200Cبندی`,
  `اداره\u200Cمیشود` and `اعلان\u200Cشده`; avoid `بازارگاه`, `تلرانس`,
  `جهت هنری`, `آزادسازی` and `تحویل و تحول`.
- Both: confirm the brand transliterations `افغان فوټیان` / `افغان فوتین` and
  whether the full legal name should remain Latin in formal metadata.
- Legal drafts are still drafts and require qualified legal review in addition
  to language review.
